# AGENTS.md — правила для любых AI-агентов

Проект: AI-редактор текста для iPhone (тестовое задание, 4 часа подряд).
Перед работой прочитай `docs/task.md` (задание, решения, UI-референс, модель данных)
и `docs/plan.md` (шаги, ветки, владение файлами).

## Порядок работы

1. Бери **один** следующий невыполненный шаг своей ветки из `docs/plan.md`. Не забегай вперёд.
2. Перед кодом коротко опиши, что собираешься сделать и какие файлы затронешь.
3. После изменений: `scripts/sim.sh build`, затем тесты (объём — раздел «Тесты» ниже).
   Шаг не готов, пока сборка и эти тесты не зелёные.
4. Новые строки интерфейса: после сборки `python3 scripts/sync_strings.py`
   (`xcodebuild` сам ключи в каталог не дописывает), `--check` перед коммитом.
5. Коммит: маленький, одно логическое изменение, сообщение на английском в повелительном
   наклонении (`Add word diff`, `Handle 429 with retry`). Не коммить `build/`, `.tools/`,
   `*.xcodeproj`, `.DS_Store`.
6. Решение отличается от плана — сначала обнови `docs/task.md` («Решения») и/или
   `docs/plan.md` («Журнал отклонений»), потом код.
7. Шаг с 👤 — остановись и попроси пользователя сделать его часть; не обходи.
8. Перед UI-задачей сверься со скриншотами в `docs/reference/` и разделом «UI-референс» в
   `docs/task.md`. Если скриншот и UI-референс расходятся — прав UI-референс.

## Тесты

- После каждого шага: сборка + только тесты, которые ты написал или которые покрывают
  изменённый код: `scripts/sim.sh test -only-testing:<Target>/<TestClass>`.
- UI-тесты — только свои (свой файл в `AIEditorUITests`), не весь таргет.
- Полный прогон (`scripts/sim.sh test` без фильтра) — только в шагах 1.2a и 3.1
  `docs/plan.md` или по явной команде пользователя.
- Сломалось что-то вне твоей зоны — не чини молча: сообщи и спроси.

## Команды

```bash
xcodegen generate                      # после изменения project.yml или новых файлов (sim.sh делает сам)
scripts/sim.sh                         # найти/создать свой симулятор «AIEditor-<ветка>», печатает UDID
scripts/sim.sh build                   # сборка под свой симулятор
scripts/sim.sh test -only-testing:AIEditorTests/WordDiffTests     # свои тесты после шага
scripts/sim.sh test -only-testing:AIEditorUITests/EditorUITests  # свой UI-тест
scripts/sim.sh test                    # полный прогон — только 1.2a, 3.1 или по команде
scripts/sim.sh run -- -mockData        # сборка + установка + запуск с launch-аргументами
scripts/sim.sh --ios18 test            # то же на «AIEditor-<ветка>-ios18»
python3 scripts/sync_strings.py        # дописать новые ключи в Localizable.xcstrings
python3 scripts/export_ai_logs.py      # выгрузить логи сессий в ai-logs/
```

- `AIEditor.xcodeproj` генерируется и не коммитится — правь только `project.yml`.
- `Build.command` — для проверяющего (двойной клик). Агенты его не меняют; запускают только
  на финальной проверке: `NO_PAUSE=1 ./Build.command`.
- DEBUG launch-аргументы: `-mockData`, `-mockOffline`, `-mockError 429|401|403|500|offline`,
  `-mockSlowStream`, `-mockDictation`. Сценарии ошибок проверяем ими, а не правкой кода.

## Архитектура (не отступать без обновления docs/task.md)

- **MVVM.** View — только разметка и биндинги. Логика — во ViewModel (`@Observable`,
  `@MainActor`). ViewModel не импортирует GRDB.
- **Offline-first.** GRDB — единственный источник правды. UI читает только из базы через
  `ValueObservation` → `AsyncStream` (`EditRepository`). Сеть только пишет в базу через
  `EditService`. **Единственное исключение:** живой черновик стримящегося результата —
  `EditService.draftUpdates` в памяти, ViewModel накладывает его поверх правки со статусом
  `streaming`. Стрим принадлежит `EditService`, не ViewModel.
- **Слои:** `App/` (композиция, `AppContainer`), `Features/<Name>/` (View + ViewModel),
  `Domain/` (модели, протоколы, сервисы — без сторонних зависимостей), `Data/` (GRDB, Groq,
  сеть, речь, уведомления, секреты).
- Зависимости — через инициализаторы и протоколы. Синглтонов нет, кроме `AppContainer` в
  точке входа. DI-фреймворки не используем.
- Модели домена — `struct`/`enum`, `Sendable`, `Hashable` (`Domain/Models/`), протоколы —
  `Domain/Protocols/`.
- Фейки — только в `AIEditor/Mocks/` под `#if DEBUG`. `AppContainer` по умолчанию собирает
  реальные реализации; фейк подключается только своим launch-аргументом (`LaunchOptions`).
- Модель LLM — **одна** константа `LLMConfig.model`. Промпты — только в `PromptBuilding`
  (провайдер ничего к сообщениям не добавляет).
- `ConnectivityMonitoring` — подсказка для UI (баннер), а не запрет на запрос.
- Новые SPM-зависимости — только с обоснованием в `docs/task.md` и после вопроса
  пользователю. CocoaPods запрещён.

## Swift и платформа

- Минимум **iOS 18**. Всё новее — только за `#if canImport(...)` + `if #available(iOS 26, *)`
  (в т.ч. `.glassEffect` и прочий Liquid Glass). Проект обязан собираться и работать на iOS 18;
  UI проверяй на iOS 18 (`--ios18`) и iOS 26.
- Swift 6, строгая конкурентность. Не глуши предупреждения через `@unchecked Sendable` /
  `nonisolated(unsafe)` без комментария «почему». Сборка без предупреждений.
- Без force unwrap (`!`) и `try!` в продакшен-коде (в тестах можно).
- Язык интерфейса — **английский**. Каждая строка, которую видит пользователь, — через
  `Localizable.xcstrings`: `LocalizedStringKey` (литерал в `Text`/`Button`),
  `String(localized:)` или `LocalizedStringResource`; ключ — английская фраза. Никаких
  `Text(verbatim:)` и обычных `String` из кода в UI. Данные пользователя (исходник, результат,
  названия) — не строки интерфейса.
- Доки (`docs/`, `AGENTS.md`, `CLAUDE.md`, README) и комментарии — по-русски, коммиты — по-английски.
- Цвета: системные (`.primary`, `.secondary`…) **или** из `Assets.xcassets` с Light и Dark:
  `Background`, `Surface`, `Accent`, `DiffInserted`, `DiffRemoved` (в коде — `.appBackground`,
  `.appSurface`, `.appAccent`, `.appOnAccent`, `.diffInserted`, `.diffRemoved`).
  Захардкоженные RGB в коде запрещены. Шрифты системные, только Dynamic Type.
- UI — по разделу «UI-референс» в `docs/task.md`: монохром, без логотипов и фирменных цветов;
  иконки — SF Symbols.

## Секреты — строго

- **Никогда** не печатай, не логируй и не проси API-ключ. Не читай файлы, где он может быть
  открытым текстом (`.env`), и **не открывай** `AIEditor/Data/Secrets/Secrets.generated.swift`.
- Ключ попадает в проект только через `scripts/gen_secrets.py` из переменной окружения;
  запускает его **только пользователь**. Файл содержит только обфусцированные байты и
  закоммичен (он не в `.gitignore`).
- Не добавляй ключ в URL, `print`, тексты ошибок, тесты. Тест ключа проверяет только форму
  (префикс `gsk_`, длина), значения сводятся к `Bool` до `#expect`.
- Перед коммитом `git grep -lE "gsk_[A-Za-z0-9]{20,}"` должен быть пуст (только `-l`).
- В `ai-logs/` не должно быть ключей, email и путей с именем пользователя. После каждого
  раздела плана — `python3 scripts/export_ai_logs.py`, коммит только при «✓ ai-logs чистые».
  Логи Codex (`~/.codex/sessions/` за день работы) — копирует пользователь.

## Поведение, которое нельзя сломать

- Результат стримится по токенам; «Stop» отменяет `Task`, уже полученный текст
  сохраняется со статусом `cancelled`.
- В базу во время стриминга — не чаще ~2 раз в секунду + финальная запись.
- Ошибки различаются: нет сети / 429 лимит / 401 / 403 / прочее — у каждой понятный текст и
  «Retry» (`EditErrorPresentation`, таблица в `docs/task.md`). «Stop» — не ошибка.
- Без сети запрос всё равно уходит; правка становится `failed(offline)` с «Retry».
- При запуске правки в статусе `streaming` переводятся в `interrupted` (с «Retry»).
- «Retry» во время генерации ничего не делает (атомарный `claimRetry`).
- История правок переживает перезапуск; любая правка открывается из истории.

## Git при параллельной работе

- Каждая фича — своя ветка и свой worktree рядом с основным:
  `git worktree add ../ai-editor-<feature> -b feat/<feature>`.
- В `main` сливает **только пользователь** или агент **по его явной команде**.
- Запрещено: `git reset` на `main`, `push --force`, push в `main` без команды, переписывать
  чужие ветки.
- Перед слиянием: `git fetch` и проверка, что `main` не изменился с момента ответвления;
  если изменился — сначала влей `main` в свою ветку, прогони тесты.
- Существующие Domain-протоколы и модели (`Domain/Protocols`, `Domain/Models`) в фича-ветке
  **не меняй** — если нужно, остановись и спроси. Новые файлы в своей зоне (см. «Владение
  файлами» в `docs/plan.md`) — можно.
- `docs/plan.md` в фича-ветке не отмечай — шаги отмечаются в `main` после слияния.
  Отклонения и находки пиши в `docs/task.md` своей ветки (их сольют вместе с кодом).

## Симуляторы при параллельной работе

- У каждого worktree свой симулятор «AIEditor-<ветка>» (`scripts/sim.sh`); сборка,
  установка и тесты — только на его UDID (скрипт делает это сам).
- Запрещено: `simctl shutdown all`, `simctl erase all`, трогать чужие симуляторы,
  закрывать приложение Simulator.
- DerivedData — своя в каждом worktree (`build/DerivedData` внутри папки).

## Время

Работа идёт 4 часа подряд; старт и финиш пользователь фиксирует в README. После финиша
работу не продолжаем — незавершённое описываем в README («Не сделано»).

## Когда остановиться и спросить

- Нужно менять архитектуру, существующие Domain-протоколы или добавить зависимость.
- Требование из `docs/task.md` противоречит другому.
- Сборка или тесты не чинятся за 2–3 попытки — опиши, что пробовал.
